# Scientific Readiness and Reliability Audit

**Date:** 2026-10-08  
**Scope:** Core runtime (`runner/`), catalog & skill generation (`librarian/`), pipeline handoffs (`handoffs/`), documentation, automated discovery gating, website security, and execution validation on the de.NBI cloud infrastructure.  
**Platform Tested:** Linux 6.8.0-136-generic x86_64 (`denbi_instance`), Nextflow 26.04.3, Docker 29.1.3, Python 3.12.3 / 3.11.

---

## 1. Executive Summary

An exhaustive scientific and technical audit of the **nf-claw** project was conducted to establish readiness for reliable research use. The audit identified and resolved critical failure modes spanning:
1. Concurrency and outdir corruption under overlapping or resumed runs.
2. Silent divergence during replay caused by unmonitored external configurations or mutated local input datasets.
3. Handoff lineage failures in pipeline chaining, including a critical domain issue in MAG metagenomic co-assembly grouping.
4. Conflation of structural file matching with analytical agreement in output verification.
5. Inaccurate documentation regarding reference genome sources (e.g. assuming remote AWS iGenomes when pipelines use local paths).
6. Permissive CI acceptance heuristics in automated pipeline discovery.
7. Vulnerable dependencies in the frontend documentation site.

Every identified issue was paired with automated regression tests, validated locally and on the dedicated de.NBI server, culminating in a 100% passing test suite (853 tests, 91% coverage) and successful real-data biological pipeline execution.

## 2. Scientific & Technical Deficiencies Resolved

### 2.1 Run Concurrency & Output Directory Locking
- **Deficiency:** Simultaneous or overlapping executions pointing to the same `--outdir` (or an accidental concurrent `--resume`) could overwrite active parameter manifests, interleave logs, or corrupt the Nextflow execution session.
- **Resolution:** Introduced POSIX sibling file locking (`runner/locking.py`, using non-blocking exclusive flock on `.{outdir.name}.nfclaw.lock`). Active runs refuse concurrent writers with `ErrorCode.ENVIRONMENT`, ensuring single-writer exclusivity throughout workflow lifetime.

### 2.2 Replay Dependency Guard & Input Snapshot Integrity
- **Deficiency:** A replay command (`provenance/commands.sh`) could execute successfully even if local input files or user-provided Nextflow config files (`-c`) had changed since the original run, producing divergent scientific results without warning.
- **Resolution:** Implemented `runner/replay_guard.py` and pre-execution dependency hashing in `runner/provenance.py`. The runner snapshots local input files (including paths referenced in samplesheets), external configs, and pipeline source commits. The replay script executes a standalone dependency validator before launching Nextflow, halting immediately if local inputs or configs have been modified or deleted.

### 2.3 Chaining Lineage & Metagenomic Assembly Integrity
- **Deficiency:** In pipeline chaining:
  - If upstream output files were altered or deleted after a successful stage, downstream stages would ingest modified data without detecting the breach of provenance.
  - In `handoffs/fetchngs/mag.json` and `handoffs/detaxizer/mag.json`, all demultiplexed samples were hard-coded to co-assembly group `"0"`. In the nf-core/mag pipeline, identical group identifiers trigger pooled/co-assembly and multi-sample binning across distinct biological samples, which is scientifically invalid for independent samples and drastically alters taxonomic recovery.
- **Resolution:**
  - Strengthened `runner/handoff.py` and `runner/chain.py` to cryptographically verify all upstream source files against the upstream stage's `outputs.sha256` before handoff materialization.
  - Updated MAG handoffs to assign individual samples their own group (`"group": "{sample}"`), preserving sample separation while documenting how to supply study-specific pooling via inline handoffs.

### 2.4 Precision in Output Verification
- **Deficiency:** Prior verification logic treated all file differences as benign timestamps, stating that "differing bytes are expected" without distinguishing metadata from scientific data changes.
- **Resolution:** Redesigned `runner/verify.py` to decouple structural equality (identical file sets) from byte equality. Added `--strict` verification flag. Clear distinction is made in reporting: structural equivalence confirms identical file inventory, but does not certify identical scientific values; differing bytes are flagged for domain-specific inspection.

### 2.5 Truthful Reference Genome Attribution
- **Deficiency:** Skill documentation previously inferred that any `--genome` flag was fetched from remote AWS iGenomes, even for pipelines configuring local reference directories or pipelines declaring `--igenomes-ignore true`.
- **Resolution:** Updated `librarian/write_skill.py` to inspect `igenomes_base` and `igenomes_ignore` defaults, explicitly noting local configs or disabled lookups rather than asserting remote S3 dependencies.

### 2.6 Strict Automated Discovery Gate
- **Deficiency:** `scripts/nextflow_accept.sh` previously accepted pipelines if Nextflow printed preliminary banner text even if remote test data staging failed with exit code 1.
- **Resolution:** Enforced strict exit code 0 requirement for pipeline acceptance. Staging failures are categorized as `staging-unverified` and rejected from automated discovery PR merges.

### 2.7 Frontend Security Hardening
- **Deficiency:** The Next.js website contained outdated dependencies with reported npm audit vulnerabilities.
- **Resolution:** Upgraded Tailwind CSS to 4.3.3 and modernized PostCSS tooling, resolving reported vulnerabilities with zero typecheck or build errors across all 109 static routes.

## 4. Scope and Limitations

- **Wrapper & Orchestration Role:** nf-claw provides CLI orchestration, schema validation, chaining handoffs, and provenance tracking. It wraps pinned nf-core releases unmodified. Scientific accuracy of individual biological algorithms (e.g., STAR, BWA-MEM, FreeBayes, SPAdes) is governed by upstream software and appropriate selection of reference data and parameters.
- **Reproducibility Scope:** Replay guards freeze local samplesheets, local files, configuration files, parameters, and pinned git commits. Unpinned external URLs, remote S3 buckets, and unpinned container tags (when not pinned by hash digest) remain external dependencies subject to network availability.
